# 생기부 도우미 인계 문서

작성 기준일: 2026-06-30

이 문서는 새 Codex 세션에서 현재 로컬 프로젝트를 안전하게 이어가기 위한 기준 문서다. 현재는 1단계 화면과 더미 생성 흐름을 만드는 중이며, OpenAI API와 파일 본문 분석은 아직 구현하지 않는다.

## 1. 프로젝트 목적

초등학교 교사가 학생별 수행평가 결과와 교과별 참고자료를 바탕으로 학기말 종합의견을 빠르게 작성하고 직접 수정하도록 돕는 교사 전용 업무 도구다.

현재 핵심 기능은 `교과 평어 작성기`다. 최종적으로는 교과, 평가 계획, 영역별 평가결과, 수행평가지, 예시문과 추가 지시사항을 바탕으로 학생별 종합의견을 생성하고 표에서 수정·복사·다운로드할 수 있어야 한다.

현재 단계는 UI 프로토타입이다. 실제 학교 공식 시스템이 아니며 특정 공공기관이나 서비스를 사칭하지 않는다.

## 2. 현재까지 구현된 기능

### 화면과 공통 구조

- Next.js App Router, TypeScript, Tailwind CSS 4 기반 화면
- 파스텔 블루 상단 메뉴와 `생기부 도우미` 브랜드 영역
- 왼쪽 `평가관리` 트리형 사이드바
- `학기말종합의견` 메인 업무 화면
- Pretendard 로컬 패키지를 이용한 한글 글꼴
- 데스크톱 중심의 여유 있는 파스텔 업무형 레이아웃
- 더미 월 사용량 18,420원과 30,000원 한도 배지

### 교과 평어 작성기

- 학년도, 학기, 학년, 반, 교과 조회 조건
- 접이식 생성 참고자료 및 접근 설정 영역
- 현재 버전의 평가 계획, 예시문, 추가 지시사항, 비밀번호 입력 UI
- 예시 학생 5명의 평가결과 표
- 학생 선택, 번호, 성명, 평가결과, 학기말 종합의견 직접 편집
- 체크 학생 우선 생성, 선택 학생 생성, 전체 학생 생성
- OpenAI 호출 없이 준비된 긍정 문장을 넣는 더미 생성
- 결과 복사와 UTF-8 BOM CSV 다운로드
- 행 추가, 선택 행 삭제, 전체 초기화
- 필수 입력 누락과 작업 완료 상태 안내

### 영역별 파일 등록

아래 기반 로직과 화면 연결이 완료되어 있다.

- `AreaEvidence` 타입: 영역 식별자, 영역명, 브라우저 `File` 객체
- 반영 영역 수를 1개에서 5개로 조절하면서 앞쪽 입력을 보존하는 함수
- 영역별 자료가 PDF인지 확장자로 검사하는 함수
- 평가 계획·수행평가지가 HWP, HWPX, PDF인지 검사하는 함수
- 파일 크기를 KB 또는 MB로 표시하는 함수
- 국어 기본 반영 영역 3개와 영역별 파일 업로드 UI
- 영역별 필수 PDF 누락 시 생성을 막는 컴포넌트 테스트
- 평가 계획 1개, 수행평가지 여러 개의 등록·삭제 테스트
- 기본 예시문 3종 선택과 직접 수정

## 4. 요구된 UI와 스타일 원칙

- 학교 행정 업무 화면처럼 정보 구조는 명확하게 하되 지나치게 빽빽하지 않게 만든다.
- 특정 공식 서비스의 로고, 명칭, 화면을 복제하거나 공식 서비스처럼 오해하게 만들지 않는다.
- 참고 이미지의 넓은 흰 공간, 얇은 구분선, 차분한 글자와 세련된 여백을 반영한다.
- 핵심 색은 파스텔 블루다. 강한 원색과 과도한 그림자는 피한다.
- 현재 기준 색상은 배경 `#f6f9fc`, 주요 파랑 `#79aee3` 및 `#5f98d1`, 강조 배경 `#eaf4ff`, 선 `#d8e4f0`이다.
- 한글 본문은 Pretendard를 우선 사용한다. 외부 글꼴 서버에 의존하지 않는다.
- 본문은 대체로 13~14px, 입력과 버튼은 약 32~36px 높이를 유지한다.
- 상단 메뉴, 왼쪽 트리 메뉴, 조회 조건, 접이식 참고자료, 넓은 학생 표 구조를 유지한다.
- 데스크톱을 우선하며 넓은 표는 가로 스크롤을 허용한다.
- 화려한 애니메이션, 홍보 페이지식 대형 이미지, 과도한 카드형 대시보드는 사용하지 않는다.
- 필수·선택·등록 완료 상태는 색상만이 아니라 글자와 배지로도 구분한다.

## 5. 절대 바꾸면 안 되는 부분

### 데이터와 보안

- OpenAI API 키를 브라우저 코드에 넣거나 `NEXT_PUBLIC_` 환경변수로 노출하면 안 된다.
- 향후 OpenAI 호출은 반드시 서버 라우트에서만 수행한다.
- 학생 이름, 수행평가 원문, 업로드 문서 내용, 생성 결과를 사용량 데이터베이스에 저장하면 안 된다.
- 사용량 기록에는 토큰 수, 비용, 모델, 생성 시각처럼 최소 정보만 저장한다.
- 로그에도 학생 이름과 평가 원문을 남기지 않는다.
- 현재 1단계에서는 비밀번호와 파일을 서버로 보내지 않는다. 브라우저 메모리에만 두고 새로고침 시 폐기한다.

### 현재 승인된 파일 등록 규칙

- 반영 영역 수는 교사가 1~5개 사이에서 정한다.
- 국어, 수학, 사회, 과학의 기본 영역 수는 3개이고 나머지 교과는 2개다.
- 반영할 각 영역에는 영역명과 해당 영역의 평가결과 PDF가 모두 필수다.
- 영역별 평가결과는 PDF만 허용한다.
- 평가 계획은 HWP, HWPX, PDF 한 개를 등록하는 권장 자료다.
- 수행평가지는 HWP, HWPX, PDF 여러 개를 등록할 수 있는 선택 자료다.
- 수행평가지는 선택 사항이지만 등록하면 평가 맥락을 반영해 더 적절한 평어를 만드는 데 도움이 된다고 안내한다.
- 1단계에서는 파일명, 크기, 확장자와 등록 여부만 확인한다. 파일 본문을 읽거나 분석했다고 표시하면 안 된다.
- 반영 영역 수를 줄이면 앞쪽 입력을 보존하고 초과 행만 제거한다.
- 파일의 실제 로컬 경로는 표시하지 않는다.

### 생성과 결과 UI

- 더미 생성 결과는 학기말 종합의견 textarea에 들어가고 교사가 직접 수정할 수 있어야 한다.
- 복사와 CSV 열 순서는 번호, 성명, 평가결과, 학기말 종합의견이다.
- CSV 파일명은 `교과평어.csv`이고 한글 호환을 위해 UTF-8 BOM을 유지한다.
- 학생 자료를 실제로 분석하지 않는 단계에서 분석한 것처럼 보이는 가짜 처리 지연이나 가짜 네트워크 상태를 만들지 않는다.
- 사용량 27,000원 이상은 경고, 30,000원 이상은 제한 상태라는 규칙을 유지한다.

## 6. 아직 남은 작업

### 현재 1단계에서 바로 이어서 할 작업

1. 사용자가 열린 3000 포트 화면에서 시각 배치와 실제 파일 선택 흐름을 직접 확인한다.
2. 필요하면 확인된 시각 결함만 수정하고 전체 검증을 다시 실행한다.
3. 파일 크기와 개수 제한은 사용자와 기준을 정한 뒤 구현한다.

### 이후 단계

- `app/api/generate-report/route.ts` 서버 라우트
- 서버 비밀번호 검증, 입력 길이 제한, IP 기반 요청 빈도 제한
- 월 30,000원 누적 비용 확인과 차단
- OpenAI Responses API의 JSON 응답 처리
- PDF와 HWP/HWPX 본문 추출 및 교사 확인 화면
- 학생별 영역·성취 수준 매칭 검증
- 금지어, 제품명, 외국어, 특수문자 후처리
- 최소 사용량 데이터 저장과 실제 사용량 API

표 구조가 다른 PDF나 스캔 이미지 PDF는 자동 판독이 정확하지 않을 수 있다. 이후 파일 분석을 구현할 때 추출 결과를 교사가 반드시 확인·수정하는 중간 화면이 필요하다.

## 7. 현재 오류와 불안정한 부분

- 전체 자동 테스트는 27개 모두 통과했고 타입 검사와 프로덕션 빌드도 통과했다.
- 로컬 3000 포트는 HTTP 200과 페이지 제목까지 확인했지만, 인앱 브라우저의 화면 요소 검사 연결이 반복해서 시간 제한에 걸려 완전한 시각 검증은 끝내지 못했다.
- 현재 파일 형식 검사는 확장자 기반이다. 파일 내용이나 MIME 위조 여부까지 검증하지 않는다.
- 파일 크기 함수는 1KB 미만을 모두 `0 KB`로 표시한다. 승인된 테스트에는 맞지만 더 세밀한 표시가 필요하면 요구사항 확인 후 변경한다.
- 업로드 파일은 브라우저 메모리에 놓을 예정이므로 대용량 파일 개수와 크기 제한은 아직 정해지지 않았다. 임의로 정하지 말고 사용자에게 확인해야 한다.
- 기본 셸에서 오래된 Node.js가 선택될 수 있다. 이 프로젝트는 Node.js 20.19 이상이 필요하다.
- 일부 격리 환경에서는 Next.js 빌드 중 자식 프로세스 실행 권한 오류가 날 수 있다. 코드 오류인지 실행 환경 문제인지 분리해서 확인해야 한다.

## 8. 다음 새 Codex 세션에서 가장 먼저 할 일

새 기능 범위를 넓히지 말고 다음 순서로 시작한다.

1. 이 문서와 `docs/superpowers/specs/2026-06-29-report-generator-ui-design.md`를 읽는다.
2. `docs/superpowers/plans/2026-06-30-area-evidence-uploads.md`의 Task 2부터 이어간다.
3. Node.js가 20.19 이상인지 `node --version`으로 확인한다.
4. `pnpm test:run`으로 27개 테스트가 계속 통과하는지 확인한다.
5. 3000 포트 화면에서 업로드 카드, 영역 3행, 예시문, 학생 표의 배치를 먼저 눈으로 확인한다.
6. 영역 수 변경, PDF 등록, 누락 차단, 삭제와 더미 생성 흐름을 직접 조작한다.
7. 시각 검증 전까지 OpenAI API, 파일 본문 파싱, 데이터베이스 작업을 시작하지 않는다.

## 9. 실행 및 테스트 방법

필수 조건은 Node.js 20.19 이상과 pnpm 11이다.

```bash
pnpm install
pnpm dev
```

브라우저에서 다음 주소를 연다.

```text
http://localhost:3000
```

검증 명령은 다음과 같다.

```bash
pnpm typecheck
pnpm test:run
pnpm build
```

현재 중단 상태를 먼저 확인할 때는 다음 두 테스트를 따로 실행한다.

```bash
pnpm test:run -- tests/report-ui.test.ts
pnpm test:run -- tests/report-generator.test.tsx
```

브라우저 검증에서는 1440px 안팎의 데스크톱 너비에서 상단바, 사이드바, 조회 조건, 접이식 자료 영역과 학생 표가 겹치지 않는지 확인한다. 이후 업로드 UI가 구현되면 영역 수 변경, PDF 등록, 필수 누락 차단, 더미 생성, 파일 삭제까지 확인한다.

## 10. 환경변수 이름

현재 1단계 UI 실행에는 환경변수가 필요하지 않다. `.env.local`은 아직 만들 필요가 없다.

서버 기능을 구현하는 이후 단계에서 필요한 이름은 다음과 같다. 실제 값이나 API 키는 이 문서에 기록하지 않는다.

```text
OPENAI_API_KEY
OPENAI_MODEL
MONTHLY_BUDGET_KRW
USD_KRW_RATE
INPUT_PRICE_PER_1M_USD
OUTPUT_PRICE_PER_1M_USD
TEACHER_ACCESS_PASSWORD
DATABASE_URL
```

`OPENAI_API_KEY`에는 절대 `NEXT_PUBLIC_` 접두사를 붙이지 않는다.

## 11. 작업 원칙

- 불명확한 파일 크기 제한, 파일 수 제한, PDF 추출 방식, 교과별 영역 자동명은 임의로 정하지 말고 사용자에게 질문한다.

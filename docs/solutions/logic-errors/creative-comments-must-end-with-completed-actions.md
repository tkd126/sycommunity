# 창체 평어는 활동 명명이 아니라 완료된 행동으로 끝내기

## Problem

창체 평어 생성 지시에서 명사형 종결만 요구하면 모델이 `과정임`, `활동임`, `형성임`처럼 문법 형식만 명사형인 문장을 만들 수 있다. 이런 문장은 활동을 평가하거나 기록하지 않고 활동의 종류를 다시 명명하므로 학교생활기록부 문장으로 부자연스럽다.

## Symptoms

- `타인을 존중하는 태도 형성임.`
- `자기관리 능력 향상의 기반을 다지는 활동임.`
- `책임감과 협력의 중요성을 깨닫는 성장 과정임.`
- 문장은 길지만 실제 행동을 나타내는 서술어가 없음
- `새 학기 준비 자세를 다짐함을 보임.`처럼 완성된 명사형 종결 뒤에 다른 종결이 붙음
- `기름을 보임함`, `익힘을 보임함함함`처럼 종결이 반복됨
- 모델의 JSON 일부인 `},{`가 문장에 섞임
- `마음가짐을 다지고 자세를 다짐함`처럼 같은 서술어 계열이 한 문장에 반복됨
- `정확하게 이해하고 정확하게 해결함`처럼 동일한 부사어가 반복됨
- `자기 이해를 익힘`처럼 목적어와 서술어의 호응이 어색함
- 실천함을 다짐함, 기름을 다짐함, 높임을 다짐함, 이해함을 익힘처럼 각각은 허용된 종결이지만 두 종결이 중첩됨

## What Didn't Work

- `명사형 종결어미로 끝내라`는 지시만으로는 부족했다. `임`도 명사형이므로 모델 입장에서는 조건을 만족한다.
- 존댓말 종결을 `함`, `기름`, `익힘`으로 바꾸는 일반 후처리만으로는 이미 `임`으로 생성된 문장을 고치지 못했다.
- 평어 길이를 늘리는 것만으로는 문장 완결성이 좋아지지 않았다.
- 프롬프트 안의 `태도나 역량을 기름인지`라는 잘못된 호응이 모델 출력의 `기름을 보임` 같은 오류를 유도했고, 생성 뒤에는 문법 검증이 없었다.
- 문장 끝만 검사하면 내부의 중복 부사어, 유사 서술어 반복, 목적어·서술어 호응 오류는 정상 문장으로 오판된다.

## Solution

생성 지시에서 허용 종결과 금지 종결을 함께 제시한다.

```text
허용: 참여함, 익힘, 기름, 함양함, 이해함, 높임, 다짐함, 실천함, 탐색함
금지: 과정임, 활동임, 형성임, 기반을 다지는 활동임
```

또한 `lib/creative-activity.ts`의 정제 단계에서 이전에 생성됐거나 예외적으로 들어온 대표적인 어색한 종결을 행동 중심 문장으로 바꾼다.

```text
태도 형성임 → 태도를 형성함
기반을 다지는 활동임 → 기반을 다지는 활동에 참여함
성장 과정임 → 태도를 기름
하는 과정임 → 함
```

추가로 완성된 종결 뒤에 붙는 중복 표현과 JSON 잔여 문자를 제거하고, 최종 결과가 허용된 명사형 종결로 끝나는지 `isNaturalCreativeComment`로 검사한다.

단순히 마지막 단어가 허용 목록에 있는지만 확인하면 실천함을 다짐함도 마지막이 다짐함이므로 통과한다. 따라서 완성된 명사형 종결 + 을 + 또 다른 명사형 종결 구조를 별도 정규식으로 탐지하고 첫 번째 완성 종결까지만 남긴다. 이 공통 구조를 정제 함수와 유효성 검사 함수가 함께 사용해야 한다.

```text
다짐함을 보임 → 다짐함
기름을 보임함 → 기름
익힘을 보임함함함 → 익힘
실천함을 다짐함 → 실천함
기름을 다짐함 → 기름
높임을 다짐함 → 높임
이해함을 익힘 → 이해함
},{ → 제거
```

검사에 실패한 모델 출력은 화면에 표시하지 않고, 원래 활동명과 구분만 이용한 보수적인 안전 문장으로 대체한다. 생성 온도는 `0.2`로 낮춰 종결 변형 가능성도 줄인다.

문장 내부에는 별도 검사를 적용한다.

- `하게`, `히`, `적으로`로 끝나는 동일 부사어가 반복되면 거부한다.
- `다지고/다짐함`, `이해하고/이해함`처럼 같은 서술어 계열이 둘 이상 나오면 거부한다.
- `자기 이해를 익힘`, `태도를 익힘` 같은 알려진 목적어·서술어 불일치를 거부한다.
- 생성 지시에도 최종 JSON 작성 전 국어 문법과 중복 표현을 자체 점검하도록 명시한다.

브라우저 파일 다운로드에서는 객체 주소를 클릭 직후 폐기하지 않는다. 숨김 링크를 문서에 붙여 클릭한 뒤 제거하고, 객체 주소는 충분한 지연 후 폐기해 브라우저가 HWPX 바이트를 모두 인계할 시간을 확보한다.

생성 규칙은 `lib/creative-activity-openai.ts`, 후처리는 `lib/creative-activity.ts`에 두어 모델 출력과 애플리케이션 출력의 두 경계에서 방어한다.

## Why This Works

명사형이라는 형태 조건과 학교생활기록부에 필요한 의미 조건은 서로 다르다. 허용 동사는 학생이 실제로 참여하고 배우고 기른 행동을 완결하며, 금지 표현은 단순한 상태 명명에 그친다. 프롬프트로 생성 확률을 낮추고 결정적 후처리로 알려진 실패 패턴을 제거하면 같은 문제가 화면에 다시 나타나는 것을 줄일 수 있다.

## Prevention

- 한국어 평어 생성 테스트에서 허용 종결과 금지 종결을 모두 확인한다.
- 실제 오류 문장을 `sanitizeCreativeComment` 회귀 테스트 사례로 보존한다.
- 길이만 검사하지 말고 문장 마지막 서술어가 행동을 완결하는지도 검사한다.
- HWPX 내보내기는 생성한 파일을 다시 `HwpxReader`로 읽어 제목, 표 머리글, 활동, 평어가 보존되는지 검증한다.
- 모델 프롬프트의 한국어 문법도 회귀 테스트에서 검사한다. 특히 `기름인지`처럼 어색한 지시문을 금지한다.
- 모델 응답은 신뢰 경계 밖의 입력으로 보고, 정제 뒤 문법 검사를 통과한 문장만 화면에 전달한다.
- 종결 검증과 문장 내부 검증을 분리해 두 조건을 모두 통과해야 사용자에게 표시한다.
- 허용 종결 A와 허용 종결 B가 조사 을로 이어진 A을 B 조합도 비문으로 취급하고, 실제로 관찰된 조합을 표 기반 회귀 테스트로 보존한다.
- 한컴 프로그램 내부의 외부 웹 스크립트 오류는 문서 데이터 오류와 구분하고, 생성 파일은 ZIP 시그니처와 HWPX 재읽기로 검증한다.

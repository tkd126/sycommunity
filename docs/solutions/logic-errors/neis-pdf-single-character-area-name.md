# 나이스 PDF의 한 글자 영역명 추출 실패

## Problem

나이스에서 내려받은 교과평가 PDF는 표 안에 영역명이 존재하지만, 분석 후 “영역명을 확인하지 못했습니다”라는 경고가 표시되거나 영역명이 잘못 잡힐 수 있다. 실제 확인한 PDF에서는 영역 열 후보가 `법` 한 글자로 추출되었고, `지리 인식`, `자연환경과 인간생활`처럼 공백이 포함된 영역명은 후보 필터에서 버려졌다. 또한 페이지 경계에 걸친 학생 행 때문에 같은 학생 번호가 중복 추출되었다.

## Symptoms

- 평가 결과 PDF를 여러 개 등록한 뒤 첨부 자료 분석을 실행하면 일부 또는 전체 파일에서 영역명 확인 실패 경고가 나온다.
- PDF 자체에는 `성명`, `영역`, `성취기준` 헤더와 영역 셀이 보인다.
- 좌표 기반 추출을 확인하면 영역 열 안에서 `법`처럼 한 글자 후보가 반복된다.
- API 응답 내부 경고는 `학생 번호가 중복되었습니다: 7`처럼 페이지 이어짐 중복 번호를 가리키지만, UI에서는 이를 영역명 실패처럼 요약할 수 있다.
- `지리 인식`처럼 공백이 있는 정상 영역명이 제외되어 `해안 지형의 위치를 확인하고 지형` 같은 평가결과 문장이 영역명으로 선택될 수 있다.

## What Didn't Work

처음에는 PDF의 가로 배치나 좌표 회전이 원인일 수 있다고 보았다. 실제 PDF의 viewport 변환 후 좌표를 확인해 보니 헤더 좌표는 정상적으로 `성명 → 영역 → 성취기준` 순서로 잡혔다. 문제는 열 경계가 아니라 후보 필터였다.

## Solution

영역명 후보 필터를 `[가-힣]{2,10}`에서 공백 포함 한글 후보도 허용하는 방식으로 넓혔다. 단, 헤더나 표 라벨이 영역명으로 들어오지 않도록 `성명`, `영역`, `성취기준`, `평가요소`, `단계`, `평가결과`는 제외한다.

같은 이유로 텍스트 기반 fallback 파서도 한 글자 영역명과 여러 단어 영역명을 허용하도록 맞췄다. 다만 성취기준 코드가 있는 줄의 후보를 우선하고, 평가결과 문장 후보는 보조 후보로만 사용한다.

학생 번호는 페이지가 넘어가며 같은 행이 두 번 잡힐 수 있으므로 무조건 오류로 처리하지 않는다. 같은 번호가 반복될 때 한쪽만 성취 단계가 확인되면 확인된 값을 사용하고, 서로 다른 확정 단계가 충돌할 때만 중복 오류로 처리한다. 명렬표 역시 번호 기준으로 중복 제거한다.

## Why This Works

나이스 PDF는 셀 병합, 세로 가운데 정렬, 글꼴/문자 추출 방식 때문에 화면에 보이는 영역명이 PDF 텍스트 조각으로는 한 글자만 남을 수 있다. 기존 로직은 “영역명은 최소 2글자”라는 가정 때문에 실제 유효 후보를 버렸다. 한 글자 후보를 허용하면 이런 자료도 분석할 수 있고, 헤더 제외 목록으로 오탐을 줄일 수 있다.

또한 표 행이 페이지 끝에서 잘리면 같은 학생 번호가 다음 페이지 첫머리에 다시 나타날 수 있다. 이 경우는 실제 중복 학생이 아니라 하나의 행이 이어진 것이므로 번호 기준 병합이 필요하다.

## Prevention

- 나이스 PDF 파서는 화면에 보이는 문자열과 추출되는 텍스트 조각이 항상 같다고 가정하지 않는다.
- 영역명 테스트에는 2글자 이상 예시뿐 아니라 한 글자 영역명 예시도 포함한다.
- `지리 인식`, `자연환경과 인간생활`처럼 공백이 포함된 영역명 예시도 회귀 테스트에 포함한다.
- 페이지 경계에서 같은 학생 번호가 반복되는 예시를 회귀 테스트에 포함한다.
- 실제 PDF 문제를 디버깅할 때는 먼저 텍스트 조각과 좌표를 확인해 “좌표 문제”인지 “후보 필터 문제”인지 나눈다.

## Follow-up: 단계 텍스트가 없는 영역 PDF

2026-07-06에 확인한 `법` 영역 PDF는 영역명과 학생 번호/이름은 추출되지만 `매우잘함`, `잘함`, `보통`, `노력요함` 단계 텍스트가 PDF 텍스트층에서 0개로 확인되었다. 이 경우 파서가 임의로 단계를 추정하면 실제 평가 결과를 만들어내는 위험이 있으므로, 영역명은 유지하되 학생별 단계는 `확인 필요` 상태로 남기고 UI의 최종 표에서 교사가 직접 선택하도록 처리한다.

이 케이스의 예방 규칙은 “영역명을 찾은 것”과 “성취 단계를 확인한 것”을 분리하는 것이다. 영역명이 있더라도 모든 학생의 단계가 비어 있으면 API 응답에 영역별 경고를 포함하고, 화면은 해당 영역 열을 표시하되 선택값을 비워 두어 검토가 필요함을 분명히 보여준다.

2026-07-07에 추가로 확인한 문제는 `확인 필요` 영역을 선택 후보에서 제외하면, 교사가 평어 반영 영역 수를 3개로 지정해도 학생별 최종 반영 영역이 1~2개로 줄어들 수 있다는 점이다. 영역 선택 로직은 성취 단계가 확인된 영역을 `매우 잘함 → 잘함 → 보통 → 노력 요함` 순으로 우선 선택하되, 확인된 영역이 부족할 때는 `확인 필요` 영역도 가장 낮은 우선순위 후보로 포함해 지정한 개수를 유지해야 한다. 단, 외부 생성 요청에는 확인된 성취 단계만 보내고, 교사가 직접 확인해야 하는 영역은 화면에서 명확히 남긴다.

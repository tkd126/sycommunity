# 사용하지 않는 메뉴 정리, 분석 진행률, 평어 문장 개선 및 창체활동 연결 설계

작성일: 2026-07-20

## 1. 목표

이번 작업은 현재 구현된 교과평어 작성 흐름을 더 명확하고 안정적으로 만들고, 이미 구현되어 있으나 화면에 연결되지 않은 창체활동 작성기를 실제 메뉴에서 사용할 수 있도록 연결하는 데 목적이 있다.

핵심 목표는 다음 네 가지다.

1. 눌러도 동작하지 않는 메뉴를 제거하여 사용자의 혼동을 없앤다.
2. 첨부 자료 분석 중 경과 시간뿐 아니라 실제 처리 단계에 근거한 진행률을 표시한다.
3. 교과 평어를 현재보다 약 1.5배 구체적이고 자연스럽게 생성한다.
4. 연간 시간표를 분석해 날짜별 창체활동 평어를 생성하는 화면을 상단 메뉴에 연결한다.

## 2. 현재 상태와 원인

### 2.1 동작하지 않는 메뉴

왼쪽 사이드바에는 실제 화면 전환이나 기능이 연결되지 않은 `평가계획 관리`, `예시문 관리`, `사용량 관리` 등의 버튼이 있다. 동아리와 설정 영역에도 같은 형태의 미구현 버튼이 있다. 사용자는 버튼처럼 보이는 항목을 눌렀을 때 기능이 실행될 것으로 예상하므로, 미구현 항목은 표시하지 않는 편이 안전하다.

### 2.2 메타마스크 오류 화면

첨부 화면의 오류 호출 경로는 프로젝트 코드가 아니라 브라우저 확장 프로그램 주소인 `chrome-extension://nkbihfbeogaeaoehlefnkodbefgpgknn/scripts/inpage.js`이다. 프로젝트 안에는 메타마스크나 가상자산 지갑 연결 코드가 없다. 따라서 해당 오류는 사이트 기능이 메타마스크를 호출해서 생긴 것이 아니라, 개발 화면에 브라우저 확장 프로그램 오류가 표시된 것이다.

이번 작업에서 사용하지 않는 버튼은 제거하지만, 브라우저 확장 프로그램 자체의 오류를 애플리케이션 코드로 숨기지는 않는다. 동일 현상이 반복되면 로컬 사이트에서 해당 확장 프로그램을 끄거나 오류 화면을 닫고 새로고침해야 한다.

### 2.3 분석 진행률

현재 자료 분석 경로는 평가 계획, 수행평가지, 영역별 평가 결과 파일을 서버에서 읽고, 영역별 학생 결과를 파싱한 다음, 번호를 기준으로 명렬표를 합치는 구조다. 평가 계획과 수행평가지는 영역별 평가 결과와 병렬로 읽고 있어 기본적인 속도 최적화는 이미 적용되어 있다.

현재 화면의 경과 시간만으로는 남은 작업량을 판단할 수 없다. 다만 서버의 파일 읽기 함수는 한 파일 내부의 세부 처리율을 제공하지 않으므로, 초 단위로 임의 증가하는 가짜 퍼센트는 사용하지 않는다.

### 2.4 창체활동 화면

`CreativeActivityGenerator`와 창체 시간표 분석 및 평어 생성 API는 이미 존재한다. 그러나 `app/page.tsx`와 `AppShell`의 상단 메뉴에 연결되지 않아 사용자가 접근할 수 없다. 현재 `행동특성` 메뉴는 별도 화면이 없어 교과평어 화면으로 되돌아가는 상태다.

## 3. 화면 및 탐색 구조

### 3.1 상단 메뉴

상단 메뉴의 `행동특성`을 `창체활동`으로 교체한다.

- `교과평어`: 기존 교과평어 작성기
- `동아리활동`: 기존 동아리 활동 기록 작성기
- `창체활동`: 연간 시간표 분석 및 창체 평어 작성기
- `설정`: 관리자 승인 화면

### 3.2 왼쪽 사이드바

실제 동작하는 항목만 남긴다.

- 교과평어 화면: `학기말종합의견`, `교과평어 작성기`
- 동아리활동 화면: `동아리활동`, `동아리 활동 기록 작성기`
- 창체활동 화면: `창의적 체험활동`, `창체 평어 작성기`
- 설정 화면: `관리자 설정`, `관리자 승인`

다음 미구현 항목은 삭제한다.

- 평가계획 관리
- 예시문 관리
- 사용량 관리
- 활동 예시문 관리
- 저장본 관리
- 보안 설정
- 환경변수 점검

## 4. 첨부 자료 분석 진행률

### 4.1 표시 방식

현재 `분석 중 6개 파일 · 16초`와 같은 문구를 다음처럼 바꾼다.

`분석 중 67% · 4/6개 파일 · 16초`

버튼 또는 버튼 옆 영역에는 진행 막대도 함께 표시한다. 진행률은 실제 완료 사건이 발생할 때만 바뀐다.

### 4.2 진행률 계산

분석 작업을 다음 작업 단위로 계산한다.

1. 요청 검증과 파일 목록 확인 완료: 5%
2. 각 첨부 파일의 텍스트 추출 및 평가 결과 파싱: 전체의 80%
3. 학생 번호 기준 명렬표 병합과 실명 제거: 10%
4. 최종 응답 검증 및 화면 반영: 5%

파일 처리 구간의 진행률은 `(처리 완료 파일 수 / 전체 파일 수) × 80`으로 계산한다. 평가 계획, 수행평가지, 영역별 평가 결과를 모두 작업 수에 포함한다. 실패한 파일도 처리가 끝난 작업으로 계산하되, 성공으로 숨기지 않고 해당 파일의 경고를 별도로 표시한다.

서버 응답은 진행 사건을 순차적으로 전달할 수 있는 스트림 형식을 사용한다. 기존 일반 JSON 응답을 사용하는 테스트나 호출 경로가 있다면 호환 경로를 유지한다.

### 4.3 완료와 버튼 활성화

학생 명렬과 영역 결과가 화면 상태에 반영되는 즉시 분석 상태를 종료하고 교과평어 생성 버튼을 활성화한다. 후속 저장이나 부가 상태 갱신 때문에 생성 버튼이 추가로 잠기지 않도록 한다.

## 5. 교과 평어 문장 규칙 개선

### 5.1 길이와 구조

선택된 영역마다 반드시 한 문장을 작성한다. 반영 영역 수가 3개이면 정확히 3문장을 생성한다.

각 문장은 현재 기준보다 약 1.5배 구체적으로 작성하며, 권장 길이는 한 영역당 한글 약 55자에서 100자다. 길이만 늘리기 위한 반복 표현은 금지한다.

각 문장에는 가능한 범위에서 다음 요소를 포함한다.

1. 구체적인 학습 대상 또는 개념
2. 학생이 수행한 활동이나 사고 과정
3. 설명, 비교, 적용, 해결 등 확인 가능한 성취 내용

### 5.2 자연스러운 표현

다음과 같은 모호하고 부자연스러운 상투 표현은 단독으로 사용하지 않는다.

- 기본적인 이해를 보임
- 잘 이해함
- 잘 설명함
- 잘 수행함

대신 평가 계획과 수행평가지에서 확인되는 대상을 넣어 구체화한다.

- `기본적인 이해를 보임.` → `기본 개념의 의미와 적용 방법을 이해함.`
- `특징을 잘 설명함.` → `자료에 나타난 특징을 기준에 따라 비교하고 공통점과 차이점을 명확하게 설명함.`
- `문제를 잘 해결함.` → `문제 상황에서 필요한 조건을 찾아 해결 과정을 순서에 맞게 설명하고 알맞은 답을 구함.`

문장은 기존 규칙대로 명사형 종결 어미를 사용한다. 금지어, 외국어, 제품명 대체, 긍정적 표현 규칙도 그대로 유지한다.

### 5.3 영역 선택 우선순위

기존에 확정한 규칙을 유지한다.

1. 매우 잘함
2. 잘함
3. 보통
4. 노력 요함

성취 단계가 같은 후보 영역이 여러 개일 때만 전체 학생의 영역 분포를 고려해 특정 영역에 집중되지 않도록 선택한다. 성취 단계 우선순위를 영역 균형보다 먼저 적용한다.

## 6. 창체활동 작성기

### 6.1 입력

교사는 한 학기 전체 연간 시간표 파일 한 개를 첨부한다.

- 지원 형식: HWP, HWPX, PDF
- 예시 형식: `5학년1반 연간시간표(2026-07-03-0710).hwp`

### 6.2 추출 규칙

시간표에서 다음 표시만 추출한다.

- 창체
- 자율 또는 자
- 봉사 또는 봉
- 진로 또는 진

동아리, 동아리활동, 동 표시는 제외한다. 날짜, 활동 종류, 활동 내용을 서로 연결해 추출한다. 같은 날짜에 활동이 두 개이면 두 행으로 분리한다.

### 6.3 검토와 생성

파일 분석 후 교사가 추출된 날짜와 활동 내용을 확인하고 필요한 항목을 수정할 수 있게 한다. 그 다음 평어를 생성한다. 이 검토 단계는 복잡한 한글 시간표에서 잘못 연결된 날짜나 활동을 교사가 바로잡을 수 있도록 유지한다.

평어는 다음 규칙을 따른다.

- 활동 하나당 한 문장
- 명사형 종결 어미
- 외국어 및 제품명 사용 금지
- 가능한 한 긍정적인 내용 중심
- 활동 내용에서 벗어난 사실을 추가하지 않음

### 6.4 최종 결과 화면

최종 결과에는 사용자가 요청한 두 열만 표시한다.

| 날짜 | 평어 |
|---|---|
| 4월 7일 | 다문화 교육을 통해 다양한 문화의 특징을 이해하고 서로의 차이를 존중하며 더불어 살아가는 태도의 중요성을 느낌. |

같은 날짜의 활동이 두 개이면 같은 날짜를 가진 두 행으로 표시한다. 결과 복사와 CSV 다운로드는 유지한다.

## 7. 개인정보와 보안

- 기존 구글 로그인과 승인된 사용자만 API 호출 가능한 구조를 유지한다.
- 기존 교사 접근 비밀번호 확인을 유지한다.
- 학생 실명과 첨부 원문을 데이터베이스에 저장하지 않는다.
- 창체 시간표와 생성 결과도 서버에 영구 저장하지 않는다.
- OpenAI API 키는 서버 환경변수에서만 읽고 브라우저에 전달하지 않는다.
- 기존 월 사용 한도, 사용량 기록, 요청 빈도 제한을 변경하지 않는다.

## 8. 오류 처리

- 파일별 파싱 실패는 전체 분석 실패로 숨기지 않고 파일 이름과 함께 경고한다.
- 일부 파일만 실패하더라도 나머지 파일의 분석 결과는 확인할 수 있게 한다.
- 창체 시간표에서 대상 활동을 찾지 못하면 지원하는 표시인 `창체`, `자율`, `봉사`, `진로`를 안내한다.
- OpenAI 응답이 형식에 맞지 않으면 빈 결과를 성공으로 표시하지 않고 재시도 가능한 오류를 보여준다.
- 메타마스크 확장 프로그램 오류는 애플리케이션 오류 메시지로 바꾸거나 억지로 무시하지 않는다.

## 9. 검증 기준

### 9.1 탐색과 화면

- 미구현 사이드바 버튼이 보이지 않는다.
- 상단 `창체활동`을 누르면 창체 작성기가 열린다.
- 교과평어, 동아리활동, 창체활동, 설정 간 전환이 정상 동작한다.

### 9.2 분석 진행률

- 분석 시작 시 0%보다 큰 초기 단계가 표시된다.
- 파일 하나의 처리가 끝날 때마다 완료 파일 수와 퍼센트가 증가한다.
- 모든 파일 처리와 명렬 병합이 끝나면 정확히 100%가 된다.
- 실패 파일이 있어도 진행률이 멈추지 않고 경고가 표시된다.
- 학생 목록이 표시된 직후 평어 생성 버튼을 사용할 수 있다.

### 9.3 교과 평어

- 반영 영역 수 3개이면 학생마다 정확히 3문장이 생성된다.
- 각 문장이 서로 다른 선택 영역에 대응한다.
- `기본적인 이해를 보임`, 목적어 없는 `잘 설명함` 같은 문장이 생성 지침에 포함되지 않는다.
- 각 문장에 평가 자료에서 확인되는 학습 대상과 구체적 행동이 들어간다.
- 명사형 종결과 기존 금지어 규칙을 지킨다.

### 9.4 창체활동

- 제공된 연간 시간표 형식에서 날짜와 창체, 자율, 봉사, 진로 활동을 추출한다.
- 동아리 활동은 제외한다.
- 같은 날짜의 복수 활동은 서로 다른 행으로 나온다.
- 최종 화면에는 날짜와 평어만 표시된다.
- 제공된 종합의견 파일은 출력 형식과 문체를 확인하는 로컬 테스트 자료로만 사용하고 외부 저장소에 복사하지 않는다.

## 10. 이번 작업에서 제외하는 범위

- 행동특성 작성기 신규 구현
- 삭제한 관리 메뉴의 기능 구현
- 구글 로그인 방식 변경
- 결제 및 배포 기능 변경
- 메타마스크 확장 프로그램 자체 수정
- 첨부 원문이나 학생 실명의 데이터베이스 저장

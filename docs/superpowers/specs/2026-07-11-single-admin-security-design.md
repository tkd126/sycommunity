# 단일 관리자 보안 설계

작성일: 2026-07-11

## 목적

생기부 도우미의 관리자 권한을 서비스 소유자인 교사 한 명에게만 부여한다. 데이터베이스의 역할 값을 임의로 바꾸거나 관리자 화면에서 다른 사용자를 승격해도 관리자 API에 접근할 수 없도록 서버에서 단일 관리자 규칙을 강제한다.

## 확정된 정책

- 관리자는 한 명만 존재한다.
- 관리자의 실제 구글 이메일은 코드와 `.env.example`에 기록하지 않는다.
- 관리자의 유일한 판정 기준은 서버 환경변수 `ADMIN_EMAIL`이다.
- 이메일 비교 전 앞뒤 공백을 제거하고 소문자로 변환한다.
- 데이터베이스의 `role` 값과 화면 표시만으로 관리자 권한을 부여하지 않는다.
- 일반 사용자는 다른 사용자에게 관리자 권한을 줄 수 없다.
- 관리자 본인은 관리자 화면에서 자신의 사용 상태를 정지하거나 만료시킬 수 없다.

## 접근 방식 비교

### 선택안: 환경변수 기반 단일 관리자

`ADMIN_EMAIL`과 로그인한 구글 이메일을 서버에서 비교한다. 배포 환경마다 관리자를 안전하게 지정할 수 있고 개인정보가 코드에 남지 않는다. 데이터베이스가 잘못 수정되더라도 관리자 API는 환경변수에 등록된 계정만 허용한다.

### 제외안: 데이터베이스 역할 기반 관리자

기존 `User.role` 값을 계속 권한의 기준으로 사용한다. 관리 화면이나 직접 요청으로 역할이 변경될 수 있어 단일 관리자 규칙을 별도로 계속 방어해야 한다.

### 제외안: 코드에 관리자 이메일 직접 기록

구현은 단순하지만 개인정보가 소스 코드와 변경 기록에 남는다. 이메일 변경 시 코드 배포가 필요하므로 사용하지 않는다.

## 구조

### 관리자 설정 모듈

관리자 이메일 읽기와 정규화를 담당하는 작은 서버 전용 모듈을 둔다. `ADMIN_EMAIL`이 없거나 이메일 형식이 잘못되면 관리자 기능만 안전하게 실패하도록 명확한 설정 오류를 반환한다. 이 값은 클라이언트 번들에 포함하지 않는다.

### 세션 표시 권한

NextAuth 세션의 `role`은 로그인 이메일과 `ADMIN_EMAIL`의 일치 여부로 계산한다. 관리자 이메일이면 `admin`, 아니면 항상 `teacher`로 표시한다. 클라이언트의 역할 값은 메뉴 표시용이며 최종 권한 판정에는 사용하지 않는다.

### 서버 권한 판정

`requireAdmin()`은 다음 순서로 확인한다.

1. 로그인 세션이 존재하는지 확인한다.
2. 사용 상태가 `active`인지 확인한다.
3. `ADMIN_EMAIL` 설정이 유효한지 확인한다.
4. 로그인 이메일이 `ADMIN_EMAIL`과 일치하는지 확인한다.

데이터베이스에 `role=admin`이 들어 있어도 이메일이 다르면 접근을 거부한다.

### 관리자 사용자 변경 API

관리자 사용자 변경 API는 `subscriptionStatus`만 받는다. `role` 필드가 포함된 요청은 무시하지 않고 잘못된 요청으로 거부한다. 요청 대상이 현재 관리자 본인이면 정지·만료·대기 상태 변경을 거부한다. 다른 사용자의 승인, 정지, 만료만 허용한다.

### 관리자 화면

- 일반 사용자에게 상단 설정 메뉴를 표시하지 않는다.
- 관리자 승인 화면에서 역할 열과 관리자 승격·강등 버튼을 제거한다.
- 승인 상태 변경 버튼만 제공한다.
- 관리자 본인 행은 보호 계정임을 표시하고 상태 변경 버튼을 비활성화한다.

## 데이터 흐름

1. 사용자가 구글 로그인을 완료한다.
2. 서버가 로그인 이메일과 `ADMIN_EMAIL`을 비교해 세션 표시 역할을 계산한다.
3. 일반 사용자는 관리자 메뉴를 보지 못한다.
4. 관리자 API 요청이 들어오면 서버가 세션, 활성 상태, 관리자 이메일을 다시 확인한다.
5. 사용자 상태 변경 요청은 역할 변경과 관리자 본인 변경을 차단한 후 데이터베이스에 반영한다.

## 오류 처리

- 로그인하지 않음: `401 AUTH_REQUIRED`
- 승인되지 않은 사용자: `403 SUBSCRIPTION_REQUIRED`
- 관리자 이메일 불일치: `403 ADMIN_REQUIRED`
- `ADMIN_EMAIL` 누락 또는 형식 오류: `500 SERVER_CONFIG_ERROR`
- 역할 변경 필드 포함: `400 INVALID_REQUEST`
- 관리자 본인 상태 변경: `403 OWNER_ACCOUNT_PROTECTED`

오류 응답에는 환경변수 값이나 구글 OAuth 토큰을 포함하지 않는다.

## 환경변수

`.env.example`에는 값 없이 다음 이름만 추가한다.

```text
ADMIN_EMAIL=
```

실제 이메일은 로컬에서는 `.env.local`, 배포 시에는 서버 환경변수에만 저장한다. `NEXT_PUBLIC_` 접두사를 붙이지 않는다.

## 테스트

- 관리자 이메일 정규화 테스트
- `ADMIN_EMAIL`과 일치하는 활성 계정만 `requireAdmin()`을 통과하는 테스트
- 데이터베이스 역할이 `admin`이어도 이메일이 다르면 거부하는 테스트
- `ADMIN_EMAIL`이 없거나 잘못되면 설정 오류가 나는 테스트
- API가 `role` 필드를 거부하는 테스트
- 관리자가 자신의 상태를 변경하지 못하는 테스트
- 관리자가 다른 사용자의 승인 상태는 변경할 수 있는 테스트
- 일반 사용자에게 설정 메뉴가 보이지 않는 화면 테스트
- 관리자 화면에서 승격·강등 버튼이 사라지는 테스트

## 이번 작업에서 하지 않는 것

- 결제와 구독 자동화
- 관리자 다중화 또는 보조 관리자
- 학교 이메일 도메인 제한
- 관리자 다중 인증 강제
- 전체 보안 헤더와 배포 환경 보안 설정

이 항목들은 단일 관리자 권한 고정이 완료된 뒤 별도 보안 작업으로 다룬다.

# 생기부 도우미 2단계 문서 분석 및 평어 생성 설계

## 목표

교사가 등록한 영역별 평가결과 PDF, 평가 계획, 수행평가지를 로컬 서버에서 분석하고, 학생 이름을 외부로 전송하지 않은 채 OpenAI Responses API로 교과별 학기말 종합의견을 생성한다. 월 30,000원 한도와 교사 비밀번호, 요청 빈도 제한을 서버에서 적용하고 사용량 최소 정보만 로컬 PostgreSQL에 기록한다.

## 범위

### 포함

- 상단 메뉴의 `출결자료` 탭 삭제
- 텍스트 PDF, HWP 5.0, HWPX 본문 및 표 텍스트 추출
- 영역별 평가결과에서 학생 번호와 성취 단계 추출
- 평가 계획과 수행평가지에서 성취기준, 평가요소, 문항 내용 추출
- 교사가 추출 결과를 확인하고 수정하는 화면
- 학생 이름을 번호로 치환한 OpenAI 서버 호출
- 번호 기반 JSON 응답과 브라우저의 학생 이름 재연결
- 문체 예시 7종과 직접 수정
- 교사 비밀번호, 입력 길이, 파일 크기와 개수, IP 요청 빈도 검증
- 월 30,000원 한도, 27,000원 경고, 비용 계산과 사용량 기록
- 금지어, 제품명, 외국어, 특수문자 후처리
- 결과 직접 편집, 복사와 CSV 다운로드 유지

### 제외

- 스캔 이미지 PDF 문자 인식
- 암호화, 비밀번호 보호, DRM 적용 문서 해제
- 학생 자료와 생성 결과의 영구 저장
- 인터넷 배포와 다중 사용자 계정 시스템

지원하지 않는 문서는 우회하거나 해제하지 않고 교사에게 다시 저장한 텍스트 PDF, HWP 또는 HWPX를 등록하도록 안내한다.

## 보안 및 실행 경계

- 개발 서버는 `127.0.0.1`에만 바인딩해 이 PC에서만 접근한다.
- `OPENAI_API_KEY`는 `.env.local`과 서버 런타임에서만 읽는다.
- API 키에 `NEXT_PUBLIC_` 접두사를 붙이지 않는다.
- 브라우저에서 OpenAI를 직접 호출하지 않는다.
- 학생 이름은 문서 추출 과정에서 로컬 메모리에만 존재한다.
- OpenAI 요청에는 학생 번호, 영역별 성취 단계, 평가 내용, 예시문과 추가 지시사항만 포함한다.
- 서버 로그에 파일 원문, 학생 이름, 추출 텍스트, 생성 결과를 남기지 않는다.
- 업로드 파일과 추출 텍스트는 요청 종료 후 폐기한다.
- PostgreSQL에는 입력 토큰, 출력 토큰, 비용, 모델과 생성 시각만 저장한다.

OpenAI 호출 자체는 인터넷 통신이므로 익명화된 평가 정보와 참고자료 텍스트는 OpenAI에 전송된다. 학생 이름과 원본 파일은 전송하지 않는다.

## 전체 데이터 흐름

1. 교사가 영역별 평가결과 PDF, 평가 계획, 수행평가지를 등록한다.
2. 브라우저가 `multipart/form-data`로 `app/api/parse-documents/route.ts`에 파일을 보낸다.
3. 서버가 파일 형식, 크기, 개수와 암호화 여부를 검사한다.
4. PDF는 텍스트와 위치 정보를 추출하고 HWP 및 HWPX는 문단과 표 셀 텍스트를 추출한다.
5. 영역별 평가결과에서 영역명, 학생 번호, 성취 단계를 구조화한다.
6. 이름 열은 번호 매칭 확인에만 사용하고 분석 응답에서 제거한다.
7. 브라우저가 영역별 학생 번호와 단계를 수정 가능한 검토 표로 표시한다.
8. 교사가 분석 완료를 확인하고 평어 생성을 요청한다.
9. `app/api/generate-report/route.ts`가 비밀번호, 요청 제한, 월 예산과 본문 길이를 검사한다.
10. 서버가 번호 기반 입력만 OpenAI Responses API에 전송한다.
11. JSON 응답을 검증하고 후처리한 뒤 비용을 PostgreSQL에 기록한다.
12. 브라우저가 번호와 현재 학생 표를 연결해 이름별 결과 textarea에 반영한다.

## 문서 추출

### PDF

텍스트를 드래그할 수 있는 PDF만 지원한다. 텍스트 항목의 페이지, 좌표와 줄 정보를 이용해 표의 열 순서를 복원한다. 영역별 평가결과에서는 `반/번호`, `성명`, `영역`, `단계`, `평가결과` 같은 머리글을 탐색하되 학교와 교과에 따른 문구 차이를 허용한다.

### HWP 및 HWPX

HWP 5.0 바이너리와 HWPX ZIP/XML을 지원하는 TypeScript 파서를 서버에서 사용한다. 문단과 표 셀을 순서대로 평문으로 변환한다. 암호화·DRM 문서는 오류로 분류한다. HWP 3.x와 손상 문서는 지원을 보장하지 않는다.

### 추출 결과 검토

자동 추출 결과를 생성 근거로 즉시 사용하지 않는다. 영역별로 다음 내용을 표시한다.

- 영역 이름
- 학생 번호
- 추출된 성취 단계
- 원본에서 찾은 단계 표현
- 확인 상태와 오류 메시지

교사는 영역명과 단계를 직접 수정할 수 있다. 모든 반영 영역과 생성 대상 학생의 단계가 확인되어야 생성 버튼을 활성화한다.

## 성취 단계 정규화

허용 단계는 `매우 잘함`, `잘함`, `보통`, `노력 요함`이다. 문서에 `매우잘함`, `노력요함`처럼 공백이 생략되어도 정규화한다. 교과나 영역에 `매우 잘함`이 없으면 존재하는 단계만 사용한다. 인식하지 못한 단계는 임의로 추측하지 않고 검토 필요 상태로 둔다.

학생 매칭은 이름이 아니라 번호로 수행한다. 문서 번호와 화면 번호가 중복되거나 빠진 경우 생성을 차단하고 교사에게 수정하도록 안내한다.

## 문체 예시

다음 7종을 기본 제공한다.

1. 긍정 강조형
2. 성장 중심형
3. 협력 중심형
4. 탐구 중심형
5. 성실 참여형
6. 간결형
7. 구체적 서술형

선택한 예시는 textarea에 반영되며 교사가 직접 수정할 수 있다. 예시는 문체를 안내할 뿐 평가 계획과 학생별 성취 단계보다 우선하지 않는다.

## OpenAI 생성

기본 모델은 환경변수 `OPENAI_MODEL`을 사용하며 값이 없을 때 기존 요구사항인 `gpt-4.1-mini`를 사용한다. Responses API와 구조화된 JSON 출력을 사용한다. 최대 출력 토큰은 5,000으로 제한한다.

요청의 학생 식별자는 `studentNumber`뿐이며 이름은 포함하지 않는다. 응답은 다음 구조를 따른다.

```json
{
  "subject": "국어",
  "warning": "",
  "rows": [
    {
      "studentNumber": 1,
      "selectedLevels": "문학 매우 잘함 읽기 잘함 쓰기 매우 잘함",
      "comment": "작품 속 인물의 말과 행동을 바탕으로 마음을 이해하고 자신의 생각을 알맞은 근거와 함께 표현함."
    }
  ]
}
```

국어, 수학, 사회, 과학은 기본 3개 영역, 나머지 교과는 기본 2개 영역을 반영하되 화면에서 정한 반영 영역 수를 최종 기준으로 한다. 매우 잘함, 잘함, 보통, 노력 요함 순서로 강점을 우선하되 전체 학생의 표현과 영역 선택이 지나치게 반복되지 않게 한다.

## 후처리

`lib/sanitize.ts`에서 다음을 검사한다.

- 금지어: 모범생, 장애우, 그는, 그의, 학생은, 학생의, 어린이
- 부정적 표현: 미달함, 못함, 부족함, 어려움이 큼, 잘하지 못함
- 제품명 대체: 레고→블록 장난감, 클레이→점토, 스크래치→블록형 코딩 도구, 비티에스→대중가요
- 허용되지 않은 외국어와 특수문자
- 빈 문장, 지나치게 짧은 문장과 중복 문장

후처리로 안전하게 바꿀 수 없는 결과는 오류로 숨기지 않고 경고와 함께 교사 검토 대상으로 표시한다.

## API 처리 순서

### 문서 분석

1. 요청과 파일 개수 검증
2. 파일 크기와 확장자 검증
3. PDF, HWP, HWPX 형식별 추출
4. 암호화, DRM, 빈 본문 검사
5. 학생 번호와 성취 단계 구조화
6. 학생 이름 제거
7. 검토용 JSON 반환

### 평어 생성

1. 요청 본문 검증
2. 교사 접근 비밀번호 확인
3. 입력 길이와 출력 토큰 제한
4. IP 기반 요청 빈도 제한
5. 이번 달 누적 사용량 확인
6. 30,000원 이상이면 호출 차단
7. OpenAI Responses API 호출
8. JSON 구조 검증
9. 금지어와 표현 후처리
10. 토큰 사용량과 비용 계산
11. 최소 사용량 정보 저장
12. 번호 기반 결과 반환

## 사용량과 로컬 PostgreSQL

Prisma와 로컬 PostgreSQL을 사용한다.

```prisma
model UsageEvent {
  id           String   @id @default(cuid())
  inputTokens  Int
  outputTokens Int
  costKrw      Int
  model        String
  createdAt    DateTime @default(now())
}
```

월 누적 비용은 현재 달의 `costKrw` 합계다. 27,000원 이상이면 경고하고 30,000원 이상이면 생성을 차단한다. 동시 요청이 한도를 초과할 가능성을 줄이기 위해 호출 직전 사용량을 다시 확인한다. OpenAI 프로젝트 자체의 사용 한도도 별도로 설정하도록 README에 안내한다.

비용은 다음 환경변수로 계산한다.

```text
INPUT_PRICE_PER_1M_USD
OUTPUT_PRICE_PER_1M_USD
USD_KRW_RATE
```

## 오류 처리

- 일부 문서만 실패하면 성공한 분석 결과는 유지하고 실패한 파일만 다시 등록하게 한다.
- 스캔 PDF는 텍스트가 없다는 오류를 표시한다.
- 암호화·DRM 문서는 지원하지 않는 보호 문서로 안내한다.
- 번호 중복, 누락과 알 수 없는 단계는 검토 표에서 강조하고 생성을 차단한다.
- 비밀번호 오류와 요청 빈도 제한은 구체적인 민감 정보를 노출하지 않는 메시지로 반환한다.
- OpenAI 오류와 JSON 파싱 오류는 학생 자료를 로그에 남기지 않고 일반 오류 코드만 기록한다.
- 데이터베이스 연결 실패 시 사용량 한도를 확인할 수 없으므로 안전하게 생성을 차단한다.

## 환경변수

`.env.local`에는 다음 이름을 사용한다. API 키 실제 값은 문서나 소스에 기록하지 않는다.

```text
OPENAI_API_KEY
OPENAI_MODEL
MONTHLY_BUDGET_KRW
USD_KRW_RATE
INPUT_PRICE_PER_1M_USD
OUTPUT_PRICE_PER_1M_USD
TEACHER_ACCESS_PASSWORD
DATABASE_URL
```

사용자가 API 키를 입력해야 하는 시점은 서버 라우트와 환경변수 검증이 구현된 뒤다. 그때 프로젝트의 `.env.local` 파일에 직접 붙여 넣도록 안내한다.

## 테스트와 완료 조건

- PDF 표에서 영역명, 학생 번호와 단계가 추출된다.
- HWP와 HWPX의 문단 및 표 셀에서 평가 내용이 추출된다.
- 공백이 다른 성취 단계 표현이 정상화된다.
- 학생 이름이 분석 응답과 OpenAI 요청에 포함되지 않는다.
- 추출 오류를 교사가 수정한 뒤 생성할 수 있다.
- 월 27,000원 경고와 30,000원 차단이 동작한다.
- 비밀번호 오류, 속도 제한, 입력 길이와 파일 제한이 동작한다.
- OpenAI 응답 JSON과 후처리가 검증된다.
- 사용량 데이터에는 최소 정보만 저장된다.
- 전체 타입 검사, 자동 테스트와 프로덕션 빌드가 통과한다.
- `127.0.0.1:3000`에서 핵심 흐름을 브라우저로 검증한다.

실제 학교 문서의 표 구조는 달라질 수 있으므로 대표 PDF, HWP, HWPX 파일을 각각 한 개 이상으로 확인해야 문서 추출 기능을 완료로 간주한다.

# 영역별 평가 PDF 기반 명렬표 자동 동기화 설계

## 목표

교사가 한 교과의 영역별 평가 결과 PDF를 모두 등록하면 각 PDF에서 학생 번호와 성취 단계를 읽고, PDF에 성명이 있으면 로컬 화면의 명렬표에도 반영한다. 분석된 번호 집합에 맞춰 학생 표의 행을 자동으로 만들거나 제거하며, 교사가 학생 행을 하나씩 관리하지 않게 한다.

## 데이터와 개인정보 경계

- 문서 분석 API는 번호별 성취 단계와 로컬 표시용 명렬표를 반환한다.
- 성명은 브라우저 화면의 성명 열과 검토 표에만 사용한다.
- 평어 생성 API 요청에는 성명을 넣지 않고 학생 번호와 영역별 단계만 보낸다.
- 데이터베이스에는 토큰 사용량과 비용만 기록하며 성명, 평가 원문, 생성 결과를 저장하지 않는다.
- 서로 다른 영역 파일에서 같은 번호의 성명이 다르면 첫 번째 성명을 유지하고 교사에게 충돌 경고를 표시한다.

## 자동 행 동기화

분석된 모든 영역의 학생 번호와 명렬표 번호를 합쳐 오름차순으로 정렬한다. 그 번호 집합과 정확히 같은 수의 행을 만들고, 기존 행의 교사 수정 평어와 참고자료는 같은 번호에서 보존한다. PDF에서 읽은 성명이 있으면 기존 성명보다 우선한다. 분석 결과에 없는 기존 행은 제거한다.

## 이름 및 단계 추출

기존 PDF 텍스트 추출 결과에서 번호로 시작하는 학생 행을 찾는다. 알려진 영역명과 성취 단계 사이에 있는 2~4글자 한글 이름을 로컬 명렬표 후보로 읽는다. 이름이 삭제된 PDF처럼 성명을 확정할 수 없으면 빈 이름으로 두고 번호와 단계만 반영한다. 영역 단계는 매우 잘함, 잘함, 보통, 노력 요함으로 정규화한다.

## 화면

- 문서 분석 완료 즉시 학생 표의 행 수와 성명을 자동 동기화한다.
- 영역별 평가 단계 확인 표에 성명 열을 추가한다.
- 행 추가와 선택 삭제 버튼은 제거한다.
- 성명 입력란은 잘못 읽힌 이름을 로컬에서 교사가 바로잡을 수 있도록 편집 가능하게 유지한다.

## 검증

파서 단위 테스트, 여러 영역 명렬표 병합 및 충돌 테스트, 화면 행 자동 동기화 테스트, 평어 생성 요청에 성명이 포함되지 않는 개인정보 경계 테스트를 실행한다. 전체 테스트, 타입 검사, 프로덕션 빌드와 실제 로컬 화면을 확인한다.

# 생기부 도우미 교과 평어 작성기 UI 설계

## 목표

초등학교 교사가 학생별 수행평가 결과와 참고자료를 입력하고 교과별 학기말 종합의견을 작성하는 업무 화면의 1단계 뼈대를 구현한다. 이번 단계는 실제 OpenAI API, 데이터베이스, 서버 인증을 포함하지 않으며 더미 생성 결과가 수정 가능한 표에 들어가는 흐름까지 제공한다.

## 범위

### 포함

- Next.js App Router, TypeScript, Tailwind CSS 기반 단일 업무 화면
- 파란 상단 메뉴, 왼쪽 평가관리 사이드바, 메인 업무 영역
- 조회 조건, 접이식 생성 참고자료, 도구 버튼, 학생별 입력 표
- 교과별 반영 영역 수 선택과 영역별 필수 평가결과 PDF 등록
- 평가 계획 파일과 선택 수행평가지 등록
- 편집 가능한 기본 종합의견 예시 3종
- 더미 교과 평어 생성, 행 추가, 선택 삭제, 초기화
- 선택 학생 생성과 전체 학생 생성
- 결과 복사와 한글 CSV 다운로드
- 더미 월 사용량 및 상태 배지
- 입력 누락 안내와 직접 수정 가능한 생성 결과

### 제외

- OpenAI API 및 서버 라우트
- Prisma, Supabase, PostgreSQL 등 데이터베이스 연동
- 실제 비밀번호 인증 및 접근 제어
- 실제 토큰 비용 계산과 월 한도 차단
- 학생 자료의 영구 저장
- 업로드한 PDF 및 한글 파일의 본문 추출과 학생별 성취 수준 자동 판독

제외 항목은 2단계 이후 서버 기능을 구현할 때 추가한다. 이번 단계의 교사 비밀번호는 생성 전 입력 여부만 검사하며 저장하거나 전송하지 않는다. 업로드 파일도 브라우저 메모리에만 두고 파일명, 크기, 형식, 필수 등록 여부만 확인한다. 파일 내용을 실제 생성 근거로 사용했다고 표시하지 않는다.

## 선택한 화면 방향

비교한 세 안 중 접이식 업무형을 사용한다. 상단의 조회 조건 아래에 평가 계획, 예시문, 추가 지시사항, 비밀번호를 담는 접이식 영역을 둔다. 접었을 때 입력 완료 상태를 보여 주어 학생 표가 화면의 대부분을 차지하도록 한다. 고정형보다 학생 행을 많이 볼 수 있고, 좌우 분할형보다 종합의견 textarea의 가로 폭을 넓게 확보한다.

업무 시스템의 명확한 정보 구조는 유지하되 기존 지시의 조밀한 화면보다 여백을 늘린다. 참고 이미지에서 공통으로 보이는 넓은 흰 공간, 얇은 구분선, 차분한 글자, 낮은 채도의 색상을 적용한다. 쇼핑몰이나 홍보 페이지처럼 이미지 중심으로 만들지는 않으며, 교사가 여러 학생의 내용을 편집하는 표 중심 도구라는 목적을 우선한다.

## 시각 체계

### 색상

- 전체 배경은 차가운 흰색에 가까운 `#f6f9fc`를 사용한다.
- 헤더와 주요 버튼은 부드러운 파스텔 블루 계열인 `#79aee3`과 `#5f98d1`을 사용한다.
- 선택 상태와 옅은 강조 배경은 `#eaf4ff`를 사용한다.
- 기본 선은 `#d8e4f0`, 진한 본문은 `#334155`, 보조 문구는 `#64748b`를 사용한다.
- 경고와 오류만 노랑과 빨강을 사용하며 화면의 대부분은 파랑, 흰색, 옅은 회색으로 제한한다.

### 글꼴

한글 본문은 프리텐다드 가변 글꼴을 사용한다. 브라우저가 외부 글꼴 서버에 접속하지 않도록 프로젝트 의존성에 포함해 로컬에서 제공한다. 대체 글꼴 순서는 `Pretendard`, `Apple SD Gothic Neo`, `Noto Sans KR`, `Malgun Gothic`, sans-serif로 둔다. 본문은 13에서 14픽셀, 제목은 18에서 22픽셀로 기존 업무 화면보다 가볍고 읽기 편하게 구성한다.

### 여백과 모양

상단바는 약 52픽셀, 사이드바는 약 232픽셀로 설정한다. 메인 영역은 24픽셀 안팎의 바깥 여백을 사용하고, 조회 조건과 참고자료 영역 사이에는 16픽셀 정도의 간격을 둔다. 입력 높이는 약 34픽셀, 버튼은 32에서 36픽셀로 하여 지나치게 작지 않게 한다. 영역은 흰색 바탕, 얇은 테두리, 6에서 10픽셀의 절제된 모서리 둥글기를 사용한다. 강한 그림자와 화려한 애니메이션은 사용하지 않는다.

## 구성 요소

### AppShell

사이트 공통 프레임을 담당한다. 높이 약 52픽셀의 파스텔 블루 상단바에 사이트 이름과 주요 메뉴를 여유 있게 배치하고, 왼쪽에는 평가관리 트리형 메뉴를 둔다. 현재 위치인 교과평어 작성기를 연한 파란 배경과 파란 왼쪽 선으로 강조한다.

### Sidebar

평가관리 제목과 학기말종합의견 아래의 하위 메뉴를 표시한다. 1단계에서는 화면 이동 없이 현재 메뉴 상태만 표현한다.

### UsageBadge

더미 월 사용량 18,420원과 한도 30,000원을 표시한다. 향후 실제 사용량 API로 교체하기 쉽도록 독립 구성 요소로 둔다. 금액에 따라 기본, 경고, 제한 스타일을 적용할 수 있는 인터페이스를 갖는다.

### ReportGenerator

전체 상호작용을 담당하는 클라이언트 구성 요소다. 조회 조건, 접이식 참고자료, 영역별 평가결과 파일, 도구 버튼, 학생 행 상태를 관리한다. 학생 데이터와 선택한 파일은 브라우저 메모리에만 존재하며 새로고침하면 초기 더미 상태로 돌아간다.

## 화면 구성

메인 제목은 학기말종합의견이며 오른쪽에 월 사용량을 둔다. 조회 조건은 학년도, 학기, 학년, 반, 교과, 반영 영역 수의 선택 상자와 조회 버튼으로 구성한다. 국어, 수학, 사회, 과학의 기본 반영 영역 수는 3개, 나머지 교과는 2개로 설정하되 교사가 1개에서 5개 사이에서 변경할 수 있다.

접이식 참고자료는 다음과 같이 구성한다.

1. 평가 계획 파일은 `.hwp`, `.hwpx`, `.pdf` 중 한 개를 등록하고 파일명과 크기, 삭제 버튼을 표시한다. 등록 권장 자료로 안내한다.
2. 영역별 평가결과는 반영 영역 수만큼 행을 자동 생성한다. 각 행에는 영역명을 입력하고 해당 영역에서 내려받은 PDF를 한 개 등록한다. 영역명과 PDF는 모두 필수이며 등록 완료 상태를 보여 준다.
3. 수행평가지는 `.hwp`, `.hwpx`, `.pdf`를 여러 개 선택 등록할 수 있다. 선택 자료임을 표시하고 등록하면 평가 맥락을 더 충실히 반영할 수 있다는 안내를 제공한다.
4. 학기말 종합의견 예시는 긍정적 서술, 성장 중심 서술, 협력 중심 서술의 3종을 기본 제공한다. 예시 선택 상자로 하나를 고르면 textarea에 반영하고 교사가 직접 수정할 수 있게 한다.
5. 추가 지시사항과 비밀번호 입력을 같은 접이식 영역에 둔다.

도구 영역에는 교과평어 생성, 선택 학생만 생성, 전체 학생 생성, 결과 복사, CSV 다운로드, 행 추가, 선택 삭제, 초기화를 배치한다. 주요 생성 버튼은 파란색, 나머지는 흰색 또는 연한 회색의 보조 버튼으로 구분한다.

학생 표의 열은 선택, 번호, 성명, 참고자료, 평가결과, 학기말 종합의견 순서다. 표는 최소 너비를 지정하고 메인 영역에서 가로 스크롤을 허용한다. 종합의견은 충분한 가로 폭을 가진 수정 가능한 textarea로 제공한다.

## 초기 데이터와 생성 흐름

초기 화면에는 서로 다른 평가결과를 가진 학생 5명을 제공한다. 이름은 실제 학생으로 오해되지 않도록 김하늘, 이가람, 박도윤, 최서윤, 정시우와 같은 예시 이름을 사용한다.

생성 전 다음 조건을 검사한다.

1. 교과가 선택되어 있어야 한다.
2. 생성 대상 학생의 성명과 평가결과가 있어야 한다.
3. 반영 영역 수와 영역별 등록 행 수가 일치해야 한다.
4. 모든 영역 행에 영역명이 입력되고 PDF가 등록되어야 한다.
5. 학기말 종합의견 예시가 있어야 한다.
6. 비밀번호 입력값이 있어야 한다.

교과평어 생성 버튼은 체크된 학생이 있으면 해당 학생만 생성하고, 체크된 학생이 없으면 전체 학생을 생성한다. 선택 학생만 생성 버튼은 선택이 없으면 안내하고, 전체 학생 생성 버튼은 전체 행을 대상으로 한다.

더미 생성 함수는 학생 번호와 평가결과를 기준으로 준비된 여러 긍정적 문장을 순환 배정한다. 결과는 학기말 종합의견 textarea에 들어가며 사용자가 즉시 수정할 수 있다. 업로드 파일은 생성 가능 여부 확인에만 사용하고 내용을 읽었다고 가장하지 않는다. API 호출처럼 보이는 지연이나 가짜 네트워크 상태는 만들지 않는다.

## 파일 등록 동작

- 영역별 평가결과는 PDF만 허용하고 잘못된 확장자는 즉시 안내한다.
- 평가 계획과 수행평가지는 한글 문서와 PDF를 허용한다.
- 브라우저 보안상 실제 파일 경로는 표시하지 않고 파일명과 사람이 읽기 쉬운 크기만 표시한다.
- 삭제하면 해당 등록 상태를 즉시 미완료로 되돌린다.
- 반영 영역 수를 줄이면 앞쪽 영역 입력은 보존하고 초과 행만 제거한다. 다시 늘리면 빈 행을 추가한다.
- 교과를 변경하면 해당 교과의 기본 영역 수를 제안하되, 이미 파일이 등록된 경우 현재 설정을 유지한다.

## 표 편집 도구

- 행 추가는 다음 번호를 가진 빈 행을 표 끝에 추가한다.
- 선택 삭제는 체크된 행을 제거하고 선택이 없으면 안내한다.
- 초기화는 확인 창 이후 조회 조건과 학생 표, 참고자료를 초기 상태로 되돌린다.
- 참고자료 열의 자료 입력 버튼은 접이식 참고자료 영역을 펼치고 해당 영역으로 이동한다.

## 복사와 CSV

결과 복사는 번호, 성명, 평가결과, 학기말 종합의견을 탭으로 구분한 텍스트로 클립보드에 복사한다. CSV 다운로드는 같은 열을 큰따옴표 이스케이프 처리하며 UTF-8 BOM을 붙여 스프레드시트에서 한글이 깨질 가능성을 낮춘다. 파일명은 `교과평어.csv`로 한다.

## 사용자 안내와 오류 처리

오류와 완료 메시지는 화면 상단의 작은 상태 안내 영역에 표시한다. 입력 오류는 빨간 계열, 성공 안내는 파란 계열을 사용한다. 클립보드 권한이 거부되면 복사 실패를 안내한다. 브라우저에서 CSV 저장이 불가능한 경우 다운로드 실패를 안내한다.

이번 단계의 사용량은 더미 값이므로 생성 차단에는 사용하지 않는다. 다만 `UsageBadge`는 27,000원 이상 경고와 30,000원 이상 제한 스타일을 표현할 수 있도록 구현한다.

## 접근성과 화면 밀도

모든 입력에는 보이는 레이블 또는 접근 가능한 이름을 둔다. 체크박스와 버튼은 키보드로 조작할 수 있어야 한다. 본문 글자 크기는 13에서 14픽셀을 중심으로 하고, 버튼과 입력 높이는 약 34픽셀로 맞춘다. 애니메이션은 사용하지 않는다. 영역 사이에는 충분한 여백을 두되 학생 행 내부는 한 화면에서 여러 명을 편집할 수 있을 정도의 중간 밀도를 유지한다.

## 검증

- TypeScript와 린트 검사를 통과한다.
- 단위 테스트에서 기본 생성 대상 결정, 행 추가와 삭제, 영역 수 변경, 파일 형식 검증, 필수 PDF 누락 차단, 더미 문장 반영 로직을 확인한다.
- 프로덕션 빌드가 성공해야 한다.
- 브라우저에서 접이식 영역, 생성, 직접 수정, 행 추가, 선택 삭제, 초기화, 복사, CSV 버튼의 핵심 흐름을 확인한다.
- 브라우저 콘솔 오류가 없어야 하며 데스크톱 크기에서 헤더, 사이드바, 표가 겹치지 않아야 한다.

## 이후 확장 경계

2단계에서는 더미 생성 함수 대신 `app/api/generate-report/route.ts`를 호출하도록 교체한다. 클라이언트의 학생 행 타입과 생성 결과 반영 구조는 유지하고, 서버에서 비밀번호 검증, 요청 제한, 비용 확인, 파일 본문 추출, 학생별 영역과 성취 단계 검증, OpenAI 호출, 사용량 저장을 수행한다. 표 구조가 다른 PDF와 스캔 PDF는 자동 판독이 실패할 수 있으므로 추출 결과를 교사가 확인하고 수정하는 중간 화면이 필요하다. 학생 이름과 평가 원문 및 결과는 데이터베이스에 저장하지 않는다.

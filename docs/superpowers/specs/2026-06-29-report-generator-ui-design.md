# 생기부 도우미 교과 평어 작성기 UI 설계

## 목표

초등학교 교사가 학생별 수행평가 결과와 참고자료를 입력하고 교과별 학기말 종합의견을 작성하는 업무 화면의 1단계 뼈대를 구현한다. 이번 단계는 실제 OpenAI API, 데이터베이스, 서버 인증을 포함하지 않으며 더미 생성 결과가 수정 가능한 표에 들어가는 흐름까지 제공한다.

## 범위

### 포함

- Next.js App Router, TypeScript, Tailwind CSS 기반 단일 업무 화면
- 파란 상단 메뉴, 왼쪽 평가관리 사이드바, 메인 업무 영역
- 조회 조건, 접이식 생성 참고자료, 도구 버튼, 학생별 입력 표
- 더미 교과 평어 생성, 행 추가, 선택 삭제, 초기화
- 선택 학생 생성과 전체 학생 생성
- 결과 복사와 한글 CSV 다운로드
- 더미 월 사용량 및 상태 배지
- 입력 누락 안내와 직접 수정 가능한 생성 결과

### 제외

- OpenAI API 및 서버 라우트
- Prisma, Supabase, PostgreSQL 등 데이터베이스 연동
- 실제 비밀번호 인증 및 접근 제어
- 실제 토큰 비용 계산과 월 한도 차단
- 학생 자료의 영구 저장

제외 항목은 2단계 이후 서버 기능을 구현할 때 추가한다. 이번 단계의 교사 비밀번호는 생성 전 입력 여부만 검사하며 저장하거나 전송하지 않는다.

## 선택한 화면 방향

비교한 세 안 중 접이식 업무형을 사용한다. 상단의 조회 조건 아래에 평가 계획, 예시문, 추가 지시사항, 비밀번호를 담는 접이식 영역을 둔다. 접었을 때 입력 완료 상태를 보여 주어 학생 표가 화면의 대부분을 차지하도록 한다. 고정형보다 학생 행을 많이 볼 수 있고, 좌우 분할형보다 종합의견 textarea의 가로 폭을 넓게 확보한다.

## 구성 요소

### AppShell

사이트 공통 프레임을 담당한다. 높이 40픽셀의 파란 상단바에 사이트 이름과 주요 메뉴를 배치하고, 왼쪽에는 평가관리 트리형 메뉴를 둔다. 현재 위치인 교과평어 작성기를 연한 파란 배경과 파란 왼쪽 선으로 강조한다.

### Sidebar

평가관리 제목과 학기말종합의견 아래의 하위 메뉴를 표시한다. 1단계에서는 화면 이동 없이 현재 메뉴 상태만 표현한다.

### UsageBadge

더미 월 사용량 18,420원과 한도 30,000원을 표시한다. 향후 실제 사용량 API로 교체하기 쉽도록 독립 구성 요소로 둔다. 금액에 따라 기본, 경고, 제한 스타일을 적용할 수 있는 인터페이스를 갖는다.

### ReportGenerator

전체 상호작용을 담당하는 클라이언트 구성 요소다. 조회 조건, 접이식 참고자료, 도구 버튼, 학생 행 상태를 관리한다. 학생 데이터는 브라우저 메모리에만 존재하며 새로고침하면 초기 더미 상태로 돌아간다.

## 화면 구성

메인 제목은 학기말종합의견이며 오른쪽에 월 사용량을 둔다. 조회 조건은 학년도, 학기, 학년, 반, 교과의 작은 선택 상자와 조회 버튼으로 구성한다. 접이식 참고자료에는 평가 계획, 학기말 종합의견 예시, 추가 지시사항의 textarea와 비밀번호 입력창을 둔다.

도구 영역에는 교과평어 생성, 선택 학생만 생성, 전체 학생 생성, 결과 복사, CSV 다운로드, 행 추가, 선택 삭제, 초기화를 배치한다. 주요 생성 버튼은 파란색, 나머지는 흰색 또는 연한 회색의 보조 버튼으로 구분한다.

학생 표의 열은 선택, 번호, 성명, 참고자료, 평가결과, 학기말 종합의견 순서다. 표는 최소 너비를 지정하고 메인 영역에서 가로 스크롤을 허용한다. 종합의견은 충분한 가로 폭을 가진 수정 가능한 textarea로 제공한다.

## 초기 데이터와 생성 흐름

초기 화면에는 서로 다른 평가결과를 가진 학생 5명을 제공한다. 이름은 실제 학생으로 오해되지 않도록 김하늘, 이가람, 박도윤, 최서윤, 정시우와 같은 예시 이름을 사용한다.

생성 전 다음 조건을 검사한다.

1. 교과가 선택되어 있어야 한다.
2. 생성 대상 학생의 성명과 평가결과가 있어야 한다.
3. 평가 계획 또는 예시문 중 하나가 있어야 한다.
4. 비밀번호 입력값이 있어야 한다.

교과평어 생성 버튼은 체크된 학생이 있으면 해당 학생만 생성하고, 체크된 학생이 없으면 전체 학생을 생성한다. 선택 학생만 생성 버튼은 선택이 없으면 안내하고, 전체 학생 생성 버튼은 전체 행을 대상으로 한다.

더미 생성 함수는 학생 번호와 평가결과를 기준으로 준비된 여러 긍정적 문장을 순환 배정한다. 결과는 학기말 종합의견 textarea에 들어가며 사용자가 즉시 수정할 수 있다. API 호출처럼 보이는 지연이나 가짜 네트워크 상태는 만들지 않는다.

## 표 편집 도구

- 행 추가는 다음 번호를 가진 빈 행을 표 끝에 추가한다.
- 선택 삭제는 체크된 행을 제거하고 선택이 없으면 안내한다.
- 초기화는 확인 창 이후 조회 조건과 학생 표, 참고자료를 초기 상태로 되돌린다.
- 참고자료 열의 자료 입력 버튼은 접이식 참고자료 영역을 펼치고 해당 영역으로 이동한다.

## 복사와 CSV

결과 복사는 번호, 성명, 평가결과, 학기말 종합의견을 탭으로 구분한 텍스트로 클립보드에 복사한다. CSV 다운로드는 같은 열을 큰따옴표 이스케이프 처리하며 UTF-8 BOM을 붙여 스프레드시트에서 한글이 깨질 가능성을 낮춘다. 파일명은 `교과평어.csv`로 한다.

## 사용자 안내와 오류 처리

오류와 완료 메시지는 화면 상단의 작은 상태 안내 영역에 표시한다. 입력 오류는 빨간 계열, 성공 안내는 파란 계열을 사용한다. 클립보드 권한이 거부되면 복사 실패를 안내한다. 브라우저에서 CSV 저장이 불가능한 경우 다운로드 실패를 안내한다.

이번 단계의 사용량은 더미 값이므로 생성 차단에는 사용하지 않는다. 다만 `UsageBadge`는 27,000원 이상 경고와 30,000원 이상 제한 스타일을 표현할 수 있도록 구현한다.

## 접근성과 화면 밀도

모든 입력에는 보이는 레이블 또는 접근 가능한 이름을 둔다. 체크박스와 버튼은 키보드로 조작할 수 있어야 한다. 본문 글자 크기는 12에서 14픽셀을 중심으로 하고, 버튼과 입력 높이는 약 28픽셀로 맞춘다. 애니메이션은 사용하지 않으며 데스크톱에서 많은 학생 행이 보이도록 여백을 절제한다.

## 검증

- TypeScript와 린트 검사를 통과한다.
- 단위 테스트에서 기본 생성 대상 결정, 행 추가와 삭제, 더미 문장 반영 로직을 확인한다.
- 프로덕션 빌드가 성공해야 한다.
- 브라우저에서 접이식 영역, 생성, 직접 수정, 행 추가, 선택 삭제, 초기화, 복사, CSV 버튼의 핵심 흐름을 확인한다.
- 브라우저 콘솔 오류가 없어야 하며 데스크톱 크기에서 헤더, 사이드바, 표가 겹치지 않아야 한다.

## 이후 확장 경계

2단계에서는 더미 생성 함수 대신 `app/api/generate-report/route.ts`를 호출하도록 교체한다. 클라이언트의 학생 행 타입과 생성 결과 반영 구조는 유지하고, 서버에서 비밀번호 검증, 요청 제한, 비용 확인, OpenAI 호출, 사용량 저장을 수행한다. 학생 이름과 평가 원문 및 결과는 데이터베이스에 저장하지 않는다.

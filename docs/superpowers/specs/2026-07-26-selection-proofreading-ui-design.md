# 전체선택 표준화와 평어 맞춤법 검사 설계

## 목표

교과평어, 동아리활동, 창체활동 화면의 선택 방식을 일반적인 표 UI로 통일하고, 불필요한 생성·검토 버튼을 줄인다. 모든 화면에서 생성 또는 직접 수정한 평어를 한 번에 맞춤법 검사할 수 있게 한다.

## UI 변경

- 각 표의 `선택` 머리글에 체크박스를 배치한다. 체크하면 현재 행 전체가 선택되고, 다시 해제하면 전체 선택이 풀린다. 일부 행만 선택된 경우에는 중간 상태를 표시한다.
- 별도의 `선택 관리`, `전체 선택`, `전체 선택 해제` 버튼은 제거한다. `선택 삭제`는 결과 관리 영역에 유지한다.
- 동아리 화면은 `동아리 활동 기록 생성` 버튼 하나만 유지하고 `선택 학생만 생성`, `전체 학생 생성`은 제거한다. 이 버튼은 선택 행이 있으면 선택 행을, 선택 행이 없으면 전체 행을 생성하는 현재 스마트 동작을 유지한다.
- 창체 화면의 `검토 관리`, `선택 항목 확인`, `전체 항목 확인` 버튼은 제거한다. 생성 시 날짜·시수·구분·활동 값을 자동 검증하고, 문제가 있는 행만 구체적인 오류로 안내한다. `확인 상태` 열도 제거한다.
- 창체 상단 입력부는 파일, 학기, 비밀번호, 분석 버튼을 같은 정렬 체계로 배치하고 버튼 줄바꿈과 과도한 빈 공간을 없앤다.

## 맞춤법 검사 흐름

- 교과평어, 동아리활동, 창체활동의 결과 관리 영역에 `전체 결과 맞춤법 검사` 버튼을 둔다.
- 버튼을 누르면 현재 결과가 있는 모든 행의 결과 문장만 서버로 전송한다. 학생 이름, 학생 번호, 첨부 파일, 평가결과 원문, 활동 원문은 포함하지 않는다.
- 서버는 로그인 및 승인 상태, 기존 교사 접근 비밀번호, 요청 빈도, 월 사용 한도를 확인한 뒤 OpenAI Responses API로 한국어 맞춤법·띄어쓰기·문법·중복 표현만 교정한다.
- 교정 과정에서 사실이나 평가 수준을 추가·삭제하지 않고, 명사형 종결과 기존 문장 수를 유지한다.
- 검사 직전 결과를 화면 메모리에 보관하고 `검사 전으로 되돌리기`를 제공한다. 새로 검사하면 직전 상태가 새 백업이 된다.
- 결과가 없는 경우 API를 호출하지 않고 안내한다. 일부 결과가 누락되거나 형식이 잘못되면 전체 결과를 적용하지 않는다.

## 서버 및 비용·개인정보 경계

- 공통 서버 라우트 `app/api/proofread/route.ts`와 테스트 가능한 `handler.ts`를 추가한다.
- 요청은 임의 행 식별자와 결과 문장만 포함한다. 식별자는 응답을 화면 행에 되돌려 놓는 용도로만 사용하고 데이터베이스에 저장하지 않는다.
- 토큰 사용량과 비용만 기존 사용량 기록에 저장한다. 교정 원문과 결과는 로그와 데이터베이스에 남기지 않는다.
- 한 요청의 행 수와 전체 글자 수, 출력 토큰을 제한한다. 많은 행은 화면에서 안전한 크기로 나눠 순차 처리하고 진행 상태를 표시한다.

## 테스트

- 세 표의 머리글 체크박스로 전체 선택·해제 및 일부 선택 중간 상태가 동작하는지 확인한다.
- 동아리 보조 생성 버튼과 창체 검토 관리 버튼이 사라졌는지 확인한다.
- 창체는 별도 확인 동작 없이 유효한 행을 생성할 수 있고 잘못된 행은 막는지 확인한다.
- 맞춤법 검사 요청에 이름·번호·원문 자료가 포함되지 않는지 확인한다.
- 교정 결과 적용, 누락 응답 거부, 검사 전 결과 복원이 동작하는지 확인한다.
- 서버 인증·승인·비밀번호·예산·입력 제한과 사용량 기록을 API 테스트로 확인한다.

## 범위 제외

- 외부 맞춤법 검사 서비스 연동, 실시간 입력 중 검사, 맞춤법 사전 관리, 학생 개인정보 저장은 이번 변경에 포함하지 않는다.

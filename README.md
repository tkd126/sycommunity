# 생기부 도우미

초등학교 교사가 교과별 평가 자료를 바탕으로 학기말 종합의견을 작성하고 편집하는 로컬 업무 도구입니다.

## 구현 기능

- 파스텔 블루 업무 화면, 평가관리 사이드바, 과목별 메모리 작업공간
- 평가 계획, 수행평가지, 영역별 평가결과의 파일 선택 및 드래그 앤 드롭
- 평가결과 PDF에서 영역명 자동 추출 및 교과별 반영 영역 수 설정
- 평가 계획 및 수행평가지 PDF, HWP, HWPX 텍스트 추출
- 학생 번호별 성취 단계 추출, 교사 확인 및 수정
- 일곱 가지 문체 예시와 추가 지시사항
- 서버 라우트에서만 OpenAI Responses API 호출
- 기본 생성 모델은 `gpt-5.6-terra`이며 지연과 추론 비용을 줄이기 위해 `reasoning.effort`를 `none`으로 고정
- 학생 이름을 제외하고 번호와 성취 단계만 OpenAI에 전송
- 원래 성명은 응답에서 제거하고 번호를 `1번 학생` 형식으로 익명 표시
- 분석 전에는 학생 표를 숨기고 분석된 번호 수에 맞춰 행을 자동 생성
- 높은 성취 수준을 우선하면서 동점 영역은 반 전체에 고르게 분산
- 생성 결과 직접 수정, 복사, CSV 다운로드
- PostgreSQL에 토큰 수, 비용, 모델, 생성 시각만 저장
- 월 30,000원 제한, 27,000원 경고, IP 기준 요청 제한

이미지로 스캔된 PDF는 문자 인식하지 않습니다. 글자를 드래그할 수 있는 PDF만 지원합니다. 암호 또는 배포용으로 보호된 HWP 계열 문서는 읽지 못할 수 있습니다.

## 실제 학교 자료 형식 기준

다음과 같은 학교 업무 자료가 입력된다는 전제로 처리합니다.

- 영역별 평가결과 PDF: 학생 번호, 성명, 영역, 성취기준, 평가요소, 단계, 평가결과가 표의 열로 구성된 여러 쪽 문서. 성명 칸이 비어 있어도 번호와 단계로 분석합니다.
- 학기 평가 계획 HWP/HWPX/PDF: 여러 교과가 한 파일에 들어 있고 교과, 영역, 성취기준, 평가 요소, 평가 방법, 평가 시기, 단계별 평가 기준이 반복되는 표 형식.
- 수행평가지 HWP/HWPX/PDF: 문항만 있는 학생용 양식 또는 영역, 성취기준, 평가요소, 평가방법, 평가시기와 단계별 기준안이 함께 있는 형식.

단계 표기는 `매우잘함`, `매우 잘함`, `잘함`, `보통`, `노력요함`, `노력 요함`의 공백 차이를 정규화합니다. 페이지가 90도 회전되어 저장된 가로 표 PDF도 화면 좌표로 변환해 행 단위로 분석합니다.

여러 영역 파일의 학생 번호를 합쳐 번호순으로 익명 행을 자동 구성합니다. 원래 성명은 분석 응답에 포함하지 않고 `1번 학생`, `2번 학생`처럼 표시합니다. 영역명은 PDF 표의 `영역` 열 좌표를 기준으로 자동 추출합니다.

교사가 등록한 평가 영역 수와 평어에 반영할 영역 수는 다를 수 있습니다. 학생별로 `매우 잘함`, `잘함`, `보통`, `노력 요함` 순서로 필요한 영역을 먼저 채우고, 같은 수준의 후보가 여러 개일 때만 반 전체 선택 횟수가 적은 영역을 우선해 조합을 분산합니다. 균형 때문에 더 높은 성취 수준을 제외하지 않습니다.

## 설치 및 실행

Node.js 20.19 이상, pnpm, PostgreSQL이 필요합니다.

```bash
pnpm install
pnpm prisma generate
pnpm prisma db push
pnpm dev --hostname 127.0.0.1
```

브라우저에서 `http://127.0.0.1:3000`을 엽니다. 로컬 전용 사용에서는 개발 서버를 `0.0.0.0`으로 열지 마세요.

## 환경변수

`.env.example`을 참고해 프로젝트 루트에 `.env.local`을 직접 만듭니다. 실제 API 키나 비밀번호를 채팅, 소스 코드, 로그에 넣지 마세요.

- `OPENAI_API_KEY`
- `OPENAI_MODEL`
- `MONTHLY_BUDGET_KRW`
- `USD_KRW_RATE`
- `INPUT_PRICE_PER_1M_USD`
- `OUTPUT_PRICE_PER_1M_USD`
- `TEACHER_ACCESS_PASSWORD`
- `DATABASE_URL`
- `GOOGLE_CLIENT_ID`
- `GOOGLE_CLIENT_SECRET`
- `NEXTAUTH_SECRET`
- `NEXTAUTH_URL`
- `ADMIN_EMAIL`

`OPENAI_API_KEY`에는 절대 `NEXT_PUBLIC_` 접두사를 붙이지 않습니다. 브라우저는 `app/api/generate-report/route.ts`만 호출하며 API 키는 서버에서만 읽습니다.

기본 모델과 비용 계산 단가는 다음과 같습니다. 모델이나 OpenAI 공식 단가가 변경되면 세 값을 함께 수정해야 월 사용량 표시와 차단 금액이 실제 사용액에 가깝게 계산됩니다.

```dotenv
OPENAI_MODEL=gpt-5.6-terra
INPUT_PRICE_PER_1M_USD=2.00
OUTPUT_PRICE_PER_1M_USD=12.00
```

`gpt-5.6-terra`는 OpenAI 유료 API 사용 등급에서 호출할 수 있으며 ChatGPT 구독과 API 결제는 별개입니다.

### 유일 관리자 설정

`ADMIN_EMAIL`은 서비스의 유일한 관리자 계정을 식별하는 서버 전용 환경변수입니다. 로컬에서 사용할 때는 실제 Google 계정 이메일을 프로젝트 루트의 `.env.local`에만 입력하고, 배포할 때는 호스팅 제공업체의 서버 환경변수에만 입력합니다. 관리자 이메일이 브라우저 코드에 노출되지 않도록 `NEXT_PUBLIC_` 접두사는 절대 붙이지 않습니다. `ADMIN_EMAIL`을 추가하거나 변경한 뒤에는 개발 서버 또는 배포 서버를 반드시 다시 시작해야 합니다.

PostgreSQL 연결 예시는 `postgresql://사용자:비밀번호@127.0.0.1:5432/데이터베이스명` 형태입니다. 실제 값은 로컬 환경에 맞게 설정하세요.

## 사용량 및 개인정보 구조

생성 전에 이번 달 누적 사용액을 확인하고, 30,000원 이상이면 OpenAI 호출을 차단합니다. 한 번의 요청 비용은 응답 토큰을 확인한 뒤 원 단위로 올림하여 저장합니다. 동시 요청이나 단일 요청 비용 때문에 코드상의 한도를 소폭 넘을 가능성은 있으므로 OpenAI 프로젝트 예산과 알림도 별도로 설정해야 합니다.

데이터베이스에는 다음 정보만 저장합니다.

- 입력 토큰 수
- 출력 토큰 수
- 원화 환산 비용
- 사용 모델
- 생성 시각

학생 이름, 업로드 원문, 생성 결과는 저장하지 않습니다. 파일과 화면 상태는 현재 탭의 메모리에만 있으며 새로고침하거나 창을 닫으면 사라집니다. 서버는 요청 처리 중에만 파일을 읽고, 명렬표에서 확인한 성명은 평가 계획과 수행평가지 텍스트에서도 제거한 뒤 생성 요청을 구성합니다. 서버 로그에도 학생 이름과 원문을 출력하지 않습니다.

## 검증

```bash
pnpm typecheck
pnpm test:run
pnpm build
```

실제 파일 검증 시에는 개인정보가 없는 합성 자료를 먼저 사용하세요. 실제 학생 자료를 저장소나 테스트 fixture에 추가하지 마세요.

## 배포 시 주의

Vercel에 배포한다면 모든 환경변수를 Vercel 프로젝트 설정에 등록해야 합니다. 현재 IP 요청 제한은 단일 프로세스 메모리 방식이므로 다중 서버 배포에서는 Redis 같은 공유 저장소 기반 제한으로 교체해야 합니다. 학교 개인정보 처리 지침과 OpenAI 데이터 처리 조건을 확인하기 전에는 실제 학생 자료로 외부 배포판을 사용하지 마세요.
